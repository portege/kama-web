Architecture

A technical overview of BABEH's system design — from data ingestion and storage to the search pipeline and LLM response layer.

System Overview

BABEH is a modular, API-first knowledge base platform. Each component is independently replaceable, making it straightforward to swap vector stores, language models, or deployment targets without rewiring the core logic.

Multi-Region Deployment Enterprise

On the Enterprise plan, BABEH can be deployed across multiple geographic regions simultaneously. Each region runs a fully independent BABEH instance with its own API layer and data stores, fronted by a global load balancer or DNS-based routing.

Enterprise Feature

Multi-region deployment is available on the Enterprise plan only. Contact your account manager for provisioning and architecture guidance.

Benefits of Multi-Region Deployment

BenefitDescription
Lower Latency Users are routed to the nearest region, reducing API round-trip time significantly — especially important for streaming LLM responses.
High Availability If one region experiences an outage, traffic is automatically failed over to a healthy region with no manual intervention.
Data Residency Compliance Store and process data within specific geographic boundaries to comply with regulations such as GDPR (EU), PDPA (Southeast Asia), or other local data sovereignty requirements.
Horizontal Scalability Each region scales independently. A traffic spike in one market does not affect the performance experienced by users in other regions.
Knowledge Base Sync Optionally synchronize the knowledge base, pricing, and product spec data across regions so all instances serve consistent, up-to-date information.
Deployment Models

Multi-region instances can be configured as active-active (all regions serve traffic simultaneously) or active-passive (one primary region with standby failover). The right model depends on your traffic distribution and RTO/RPO requirements.
